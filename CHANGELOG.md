# Changelog

## v2.4

### Исправлено
- **SSH-пароль на всех версиях OpenSSH** — `ssh` теперь запускается на настоящем псевдотерминале (PTY), как при живом входе, и megaconf сам отвечает на приглашение `password:`. Это снимает двойной запрос пароля на старых клиентах (OpenSSH 7.4, RHEL/CentOS 7) и полностью убирает прежнюю обвязку `SSH_ASKPASS`/`DISPLAY`/setsid (та требовала танцев вокруг управляющего терминала и версии 8.4). Механизм тот же, что у `sshpass`, и работает везде
- **Консоль-серверы (Moxa и пр.) больше не «молчат»** — раньше ssh запускался с обычным pipe на stdin, и serial-консоль за Moxa не отдавала ни баннер, ни `login:` (линия видит «неинтерактивный» вход). С PTY удалённая сессия настоящая интерактивная — приглашение приходит, ввод доходит
- **Логин/аутентификация больше не ретраятся** — повтор делается только на транспортных ошибках (`refused`, нет маршрута и т.п.); неудача логина/таймаут на фазе входа не запускает вторую попытку. Это важно для однопользовательских портов Moxa (повторный заход ловил `Connection refused` на собственную же сессию) и не приближает блокировку учётки
- **Разлогин последней командой не считается ошибкой** — если последняя команда закрывает сессию (`exit`/`logout`/`reload`), закрытие соединения трактуется как успешное завершение. Обрыв в середине списка — по-прежнему ошибка
- **Чистое завершение по Ctrl+C/таймауту** — дочерние процессы (`ssh`/`telnet` и их потомки, напр. `ProxyJump`) убиваются по группе процессов; PTY-запуск кладёт процесс в собственную сессию, поэтому групповой kill работает аккуратно

### Новое
- **Console-server режим (Moxa и т.п.)** — флаг `-M` / `--console`. Двухстадийный вход: транспорт (для SSH — пароль аккаунта Moxa, megaconf отвечает на приглашение ssh в PTY; для telnet к raw-порту транспортной аутентификации нет) и затем логин самого устройства отдельными кредами — `--login-user` (по умолчанию `= -u`) и `--login-pass` (отдельный пароль; без него переиспользуется `-p`). Дополнительно: **nudge** «тихой» serial-линии (одиночный Enter с повторами), **fast-fail** при неверном логине (мгновенный неретраябельный отказ, без повторов), одиночный `CR` как перевод строки. Подразумевает `-j 1` и `--live`. Работает и по telnet (там польза — nudge и fast-fail)
- **Порт на устройство в `devices.db`** — строка может задавать порт: `host:port`, `ipv4:port`, `[ipv6]:port`. Приоритет: порт в строке → `-P` → дефолт протокола (22/23)
- **Live-вывод** — флаг `--live` (включён автоматически в `-M`) транслирует сессию в stdout в реальном времени, а не одним блоком в конце. Форсит `-j 1`. Сырой поток идёт только в stdout; файловые приёмники (`-l`/`-J`/`-D`) остаются «чистыми»
- **Режим медленной вставки** — флаг `-S` / `--slow` отправляет ввод посимвольно с задержкой (`--char-delay <мс>`, по умолчанию 30), чтобы медленный консоль-сервер (Moxa @9600) не терял символы. Замедляется весь набираемый ввод — команды, пароли, пробел пагинации. Прерывается по `Ctrl+C`/таймауту. Проверено, что системный telnet форвардит побайтовый ввод без схлопывания в бурст

### Технически
- Транспорт переведён на PTY: `startSession()` запускает процесс на псевдотерминале через `github.com/creack/pty` (unix). Windows — фолбэк на обычных пайпах (парольная SSH-аутентификация там не поддерживается, нужны ключи/agent). Платформенное разнесено по `proc_unix.go`/`proc_windows.go` через build-теги
- Добавлена зависимость `github.com/creack/pty` (чистый Go, без CGO и без `golang.org/x/*`) — встраивается в статический бинарь, на целевой системе ничего ставить не нужно
- Разбор устройства вынесен в тип `Device{Name,Host,Port}` и `readDevices()` (через `net.SplitHostPort`)
- Внутрисессионный логин (telnet и device-логин `-M`) объединён в `loginDialog()` с фазой nudge и быстрым отказом; в `ExpectSwitchCase` добавлены сентинелы `errExpectTimeout`/`errExpectClosed` (классификация исхода через `errors.Is`)
- Диагностика ошибки берёт хвост сессии (через PTY туда попадает и stderr `ssh`, напр. `Permission denied`)
- Live-трансляция реализована как tee сырых чтений в потокобезопасный writer; в обычном режиме накладных расходов нет
- Юнит-тесты: парсинг `host:port`/IPv6, сценарии `loginDialog` (норм/nudge/fast-fail), тайминг и отмена медленной отправки, live-tee. E2E console-режима (двухстадийный вход через PTY с парольной аутентификацией + разлогин) на живом бинаре

## v2.2

### Новое
- **JSON-лог** — флаг `-J` / `--json-log` пишет результаты в JSON-файл, ключ = имя устройства, значение `{result: success/unsuccess, error (при неуспехе), out}`. `out` (вывод сессии) присутствует всегда, в том числе у неуспешных устройств
- **Лог по файлу на устройство** — флаг `-D` / `--log-dir` пишет каждое устройство в отдельный файл `<имя>.log` в указанном каталоге (каталог создаётся автоматически)

### Исправлено
- В причину ошибки неуспешного устройства теперь попадает хвост stderr ssh/telnet (`Connection refused`, `Permission denied` и т.п.) — раньше диагностика отбрасывалась и в отчёте был только бесполезный `timeout`
- Быстрый отказ при закрытии соединения — если ssh/telnet завершился сразу (refused, отказ авторизации, сразу закрытая сессия), устройство возвращается мгновенно, а не ждёт полный таймаут
- Повторная попытка (retry) теперь только на транспортных ошибках; при ошибке аутентификации повтор не делается (бессмысленно и приближает блокировку учётки)
- При неуспехе сохраняется частичный вывод сессии (раньше отбрасывался)
- Промпт больше не матчится ложно на строках-фрагментах маршрута вида `1.2.3.4>` в выводе команд
- `Ctrl+C` корректно завершает работу: дочерние ssh/telnet убиваются, лог-файл флашится и закрывается, итоговый отчёт по уже завершённым устройствам печатается (раньше `os.Exit` пропускал все эти шаги)
- Изменившийся ключ хоста после обновления прошивки больше не ломает парольную аутентификацию — добавлен `UserKnownHostsFile=/dev/null`

### Улучшено
- **SSH-пароль на уровне auth** теперь действительно работает через `SSH_ASKPASS` (бинарь служит сам себе askpass-хелпером); требует OpenSSH ≥ 8.4 на клиенте. Раньше пароль уходил в stdin-пайп и до SSH-аутентификации не доходил
- Вывод в параллельном режиме строго сериализован — баннеры подключения больше не вклиниваются в блок другого устройства
- В debug-режиме принудительно `-j 1`, иначе сырой вывод нескольких горутин перемешивается

### Технически
- Таймаут подключения SSH (`ConnectTimeout`) завязан на единый флаг `-t` — убрана зашитая константа
- Своя реализация expect завершает ожидание по EOF процесса, не дожидаясь таймаута
- Убран лишний повторный скан буфера в ветке EOF

## v2.1

### Исправлено
- Команды теперь корректно выполняются на всех устройствах — в v1.0 была ошибка из-за которой команды иногда отправлялись дважды и зависали
- Пагинация `---(more)---` на JunOS теперь обрабатывается корректно
- SSH больше не зависает на устройствах где ключ хоста изменился после обновления прошивки

### Новое
- **Telnet** — поддержка через флаг `-T` / `--telnet`, по умолчанию SSH
- **Параллельная работа** — флаг `-j N` для одновременного подключения к N устройствам
- **Inline команда** — `-C "sh ver"` без файла команд
- **Прогресс** — при запуске сразу видно к каким устройствам идёт подключение и сколько их
- **Итоговый отчёт** — в конце выводится список успешных и неуспешных устройств с причиной ошибки
- **Буферизованный вывод** — при параллельном режиме вывод по каждому устройству печатается целиком, не перемешиваясь
- **Retry** — при ошибке подключения автоматически одна повторная попытка через 5 секунд
- **Лог в файл** — флаг `-l ./output.log` пишет вывод одновременно в консоль и файл
- **Комментарии в файлах** — строки начинающиеся с `#` в `devices.db` и `commands` игнорируются
- **Порт** — `-P` меняет порт подключения (дефолт 22 для SSH, 23 для Telnet)
- **Таймаут** — единый флаг `-t` для таймаута подключения и выполнения команд

### Улучшено
- Промпт определяется универсально — работает с Cisco, JunOS, Huawei VRP, MikroTik, Eltex, D-Link без настройки
- Пагинация обрабатывается автоматически для всех вендоров (`---- More ----`, `---(more)---`, `[more 50%]`, `<more>`)
- ANSI escape-коды убираются из вывода (актуально для MikroTik)
- Все настройки из `~/.ssh/config` работают автоматически — `IdentityFile`, `ProxyJump`, `Match` и др.
- SSH agent forwarding работает через `SSH_AUTH_SOCK`

### Технически
- Убраны внешние зависимости `goexpect` и `goterm` — своя реализация без проблем с кросс-компиляцией
- Статическая линковка — бинарь не требует установки библиотек на целевой системе
- Сборка для Linux (amd64/386/arm64/arm) и macOS (amd64/arm64)
