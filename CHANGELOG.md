# Changelog

## v2.3

### Исправлено
- **Двойной запрос пароля SSH на старых клиентах** — на OpenSSH < 8.4 (например 7.4 в RHEL/CentOS 7) пароль, введённый в `megaconf -p`, спрашивался ещё раз самим `ssh` прямо в консоли. Причина: `SSH_ASKPASS_REQUIRE=force` появился только в 8.4, а старый `ssh` читал пароль из `/dev/tty`, пока есть управляющий терминал, и askpass-хелпер игнорировал. Теперь `ssh` запускается в отдельной сессии **без управляющего терминала** (setsid) — `/dev/tty` недоступен, поэтому askpass используется на всех версиях OpenSSH, и пароль больше не спрашивается повторно. Добавлен `DISPLAY` (гейт для askpass на клиентах < 8.4), `SSH_ASKPASS_REQUIRE=force` сохранён для 8.4+
- **Чистое завершение по Ctrl+C/таймауту** — дочерние процессы (`ssh`/`telnet` и их потомки, например `ProxyJump`) теперь убиваются по группе процессов, а не только сам `ssh`; раньше при `ProxyJump`/прокси могли оставаться висящие процессы
- **Разлогин последней командой не считается ошибкой** — если последняя команда в списке закрывает сессию (`exit`/`logout`/`reload`), закрытие соединения трактуется как нормальное успешное завершение, а не сбой. Обрыв в середине списка по-прежнему ошибка

### Новое
- **Console-server режим (Moxa и т.п.)** — флаг `-M` / `--console`. После установки транспорта megaconf проходит внутрисессионный логин на самом устройстве за консоль-сервером. Стадии независимы и обычно с разными кредами: транспорт — `-u`/`-p` (SSH-аккаунт Moxa либо raw-telnet к порту), логин устройства — `--login-user` (по умолчанию `= -u`) и `--login-pass` (отдельный пароль; без него переиспользуется `-p`). Дополнительно `-M` даёт: **nudge** «тихой» линии (одиночный Enter с повторами, чтобы разбудить молчащий serial-порт), **fast-fail** при неверном логине (`Login incorrect`/`% login invalid`/`access denied` → мгновенный неретраябельный отказ, без повторов — чтобы не блокировать учётку), одиночный `CR` как перевод строки (serial-friendly). Подразумевает `-j 1` и `--live`. Работает и по telnet (raw-порт → логин устройства), там польза — nudge и fast-fail
- **Порт на устройство в `devices.db`** — строка может задавать порт: `host:port`, `ipv4:port`, `[ipv6]:port`. Приоритет: порт в строке → `-P` → дефолт протокола (22/23). Голый IPv6 без порта пишется без скобок
- **Live-вывод** — флаг `--live` (включён автоматически в `-M`) транслирует сессию в stdout в реальном времени, по мере поступления, а не одним блоком в конце. Форсит `-j 1`. Сырой поток идёт только в stdout; файловые приёмники (`-l`/`-J`/`-D`) остаются «чистыми» — в `-l` пишется тот же аккуратный блок, что и при обычном прогоне
- **Режим медленной вставки** — флаг `-S` / `--slow` отправляет ввод в сессию посимвольно с задержкой, чтобы медленный консоль-сервер (Moxa с портом на 9600 и т.п.) не терял символы. Задержка между символами настраивается через `--char-delay <мс>` (по умолчанию 30). Замедляется весь набираемый ввод — команды, пароль внутри сессии (telnet/enable/device-логин `-M`), пробел пагинации; SSH-аутентификация при этом не замедляется (пароль уходит на auth-уровне через askpass, а не по медленной линии). Прерывается по `Ctrl+C`/таймауту. Проверено, что системный telnet форвардит побайтовый ввод без схлопывания в бурст

### Технически
- Платформо-зависимая логика управления процессом вынесена в `proc_unix.go` (setsid + групповой kill) и `proc_windows.go` (no-op + обычный kill) через build-теги
- Разбор устройства вынесен в тип `Device{Name,Host,Port}` и `readDevices()` (через `net.SplitHostPort`); порт стал свойством устройства, а не глобального конфига
- Внутрисессионный логин (telnet и `-M`) объединён в `loginDialog()` с фазой nudge и быстрым отказом; в `ExpectSwitchCase` добавлены сентинелы `errExpectTimeout`/`errExpectClosed` для классификации исхода через `errors.Is`
- Live-трансляция реализована как tee сырых чтений в потокобезопасный writer; в обычном режиме (`live=false`) накладных расходов нет
- Юнит-тесты: парсинг `host:port`/IPv6, сценарии `loginDialog` (норм/nudge/fast-fail), тайминг и отмена медленной отправки, live-tee. E2E console-режима (двухстадийный логин + разлогин) на живом бинаре
- Новых внешних зависимостей не добавлено

## v2.2

### Новое
- **JSON-лог** — флаг `-J` / `--json-log` пишет результаты в JSON-файл, ключ = имя устройства, значение `{result: success/unsuccess, error (при неуспехе), out}`. `out` (вывод сессии) присутствует всегда, в том числе у неуспешных устройств
- **Лог по файлу на устройство** — флаг `-D` / `--log-dir` пишет каждое устройство в отдельный файл `<имя>.log` в указанном каталоге (каталог создаётся автоматически)

### Исправлено
- В причину ошибки неуспешного устройства теперь попадает хвост stderr ssh/telnet (`Connection refused`, `Permission denied` и т.п.) — раньше диагностика отбрасывалась и в отчёте был только бесполезный `timeout`
- Быстрый отказ при закрытии соединения — если ssh/telnet завершился сразу (refused, отказ авторизации, сразу закрытая сессия), устройство возвращается мгновенно, а не ждёт полный таймаут
- Повторная попытка (retry) теперь только на транспортных ошибках; при ошибке аутентификации повтор не делается (бессмысленно и приближает блокировку учётки)
- При неуспехе сохраняется частичный вывод сессии (раньше отбрасывался)
- Промпт больше не матчится ложно на строках-фрагментах маршрута вида `1.2.3.4>` в выводе команд
- `Ctrl+C` корректно завершает работу: дочерние ssh/telnet убиваются, лог-файл флашится и закрывается, итоговый отчёт по уже завершённым устройствам печатается (раньше `os.Exit` пропускал все эти шаги)
- Изменившийся ключ хоста после обновления прошивки больше не ломает парольную аутентификацию — добавлен `UserKnownHostsFile=/dev/null`

### Улучшено
- **SSH-пароль на уровне auth** теперь действительно работает через `SSH_ASKPASS` (бинарь служит сам себе askpass-хелпером); требует OpenSSH ≥ 8.4 на клиенте. Раньше пароль уходил в stdin-пайп и до SSH-аутентификации не доходил
- Вывод в параллельном режиме строго сериализован — баннеры подключения больше не вклиниваются в блок другого устройства
- В debug-режиме принудительно `-j 1`, иначе сырой вывод нескольких горутин перемешивается

### Технически
- Таймаут подключения SSH (`ConnectTimeout`) завязан на единый флаг `-t` — убрана зашитая константа
- Своя реализация expect завершает ожидание по EOF процесса, не дожидаясь таймаута
- Убран лишний повторный скан буфера в ветке EOF

## v2.1

### Исправлено
- Команды теперь корректно выполняются на всех устройствах — в v1.0 была ошибка из-за которой команды иногда отправлялись дважды и зависали
- Пагинация `---(more)---` на JunOS теперь обрабатывается корректно
- SSH больше не зависает на устройствах где ключ хоста изменился после обновления прошивки

### Новое
- **Telnet** — поддержка через флаг `-T` / `--telnet`, по умолчанию SSH
- **Параллельная работа** — флаг `-j N` для одновременного подключения к N устройствам
- **Inline команда** — `-C "sh ver"` без файла команд
- **Прогресс** — при запуске сразу видно к каким устройствам идёт подключение и сколько их
- **Итоговый отчёт** — в конце выводится список успешных и неуспешных устройств с причиной ошибки
- **Буферизованный вывод** — при параллельном режиме вывод по каждому устройству печатается целиком, не перемешиваясь
- **Retry** — при ошибке подключения автоматически одна повторная попытка через 5 секунд
- **Лог в файл** — флаг `-l ./output.log` пишет вывод одновременно в консоль и файл
- **Комментарии в файлах** — строки начинающиеся с `#` в `devices.db` и `commands` игнорируются
- **Порт** — `-P` меняет порт подключения (дефолт 22 для SSH, 23 для Telnet)
- **Таймаут** — единый флаг `-t` для таймаута подключения и выполнения команд

### Улучшено
- Промпт определяется универсально — работает с Cisco, JunOS, Huawei VRP, MikroTik, Eltex, D-Link без настройки
- Пагинация обрабатывается автоматически для всех вендоров (`---- More ----`, `---(more)---`, `[more 50%]`, `<more>`)
- ANSI escape-коды убираются из вывода (актуально для MikroTik)
- Все настройки из `~/.ssh/config` работают автоматически — `IdentityFile`, `ProxyJump`, `Match` и др.
- SSH agent forwarding работает через `SSH_AUTH_SOCK`

### Технически
- Убраны внешние зависимости `goexpect` и `goterm` — своя реализация без проблем с кросс-компиляцией
- Статическая линковка — бинарь не требует установки библиотек на целевой системе
- Сборка для Linux (amd64/386/arm64/arm) и macOS (amd64/arm64)
